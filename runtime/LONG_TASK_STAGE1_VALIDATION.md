# 长任务阶段一验收记录

日期：2026-09-07。分支：`main`。

## 交付范围

- 统一 `RunConfig`、`ContextRevision`、`StepInput` 和 `model_calls`；删除旧快照、Manifest、选择器及旧数据库迁移。当前 Session schema 10、Journal schema 7、协议 4。
- 模型上下文窗口和输出预留可配置，默认 32,768/4,096；配置变化不会改变已经提交的 Run。
- 默认总预算 100 次模型调用、3,600 秒；输入框可调整。一次 Provider 请求对应一次调用尝试，HTTP adapter 不再内部重试。
- 模型输入按保守 token 上界计算；Memory 正文与包装分别计量，按剩余空间选择完整记录，被省略的记录保留原因。
- `process_start/read/wait/stop` 最小完整链路，可信工具 Item 绑定进程身份；分页日志、整树清理、重复启动幂等、不同参数冲突拒绝、重启后未知状态。
- 桌面显示排队/运行/结束、耗时和调用消耗；命令卡片区分启动、运行、退出、未知，保留输出和真实退出码。

## 重点验证

1. 连续 30 次模型调用和 29 次工具操作完成任务，计数及历史在投影重建后保持一致。
2. 1 秒时限能取消不主动检查 CancellationToken 的阻塞 Provider，保留早期 request ID、模型 ID 与部分文字，usage 保持未知。
3. 真实命令在时限到达后停止，父/子进程退出，已捕获输出和取消结果保留。
4. 命令启动落盘后模拟 Runtime 中断，恢复时标为未知，不按旧 PID 重新认领，也不再次启动。
5. 新版本历史、文件差异和进程投影可重建；错误作用域、预算与进程步骤归属会被拒绝。
6. 同一客户端请求确认丢失后重发不会新建 Run；同一 ID 改写预算会被拒绝。
7. 失败之后的实际模拟 Provider 请求包含已经执行的工具事实；部分助手回答不会冒充完成结果。
8. 较长的 Memory 不再阻断默认窗口中的普通新消息，缺失内容记录为预算省略；原始 Memory 不被修改。
